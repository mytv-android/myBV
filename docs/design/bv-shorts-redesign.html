刷刷重设计

补上弹幕、进度调整和播放菜单，同时把手机、平板、电视三端各自别扭的操作理顺。下面的原型都能直接操作，每条改动都对应到现有代码和要改的文件。

规则一点一下，停下来操作

单击暂停后，进度条变粗、出现把手和时间，中间出现播放键。电视上确认键暂停后信息完整显示。

规则二横着划，就是调进度

手机和平板在画面任意位置横滑拖进度；电视 ←→ 直接快退快进，和主播放器一样。

规则三只有一个菜单

弹幕、倍速、画质、播完后、稍后再看收进同一份菜单。手机是底部面板，平板是右栏的一页，电视用菜单键或长按确认打开。

原则

四条规则

一个动作一个手势

不再靠按压时长或滑动方向的细微差别区分两件事。电视 ← 的短按 / 按住、手机的左滑进主页都拆掉。

跟主播放器同一套习惯

菜单键开菜单、←→ 快进退、长按确认开菜单、横滑拖进度、菜单的分组和选项，全部照搬主播放器。

画面顶天立地

画面贴满所在区域，能少量裁切铺满就铺满；空出来的地方放信息和评论，不留黑边，不加内边距和圆角框。

一份菜单，三种外壳

菜单内容是同一个模型（ShortsMenuState），手机、平板、电视只换容器，不各写一套。

手机

手机：点一下停，横着划

原型可以直接操作：单击暂停，双击点赞，长按 2×，横向拖动调进度，鼠标上下拖切条。右上「弹」开关弹幕，「⋯」打开菜单。

暂停就是操作态

单击暂停：中间出现播放键，进度条从 2dp 细线变成 6dp 带把手的拖动条，左上显示「01:12 / 02:40」。继续播放后收回。

横滑拖进度

画面任意位置左右划，过 10dp 且横向分量大于竖向 1.2 倍才进入拖动，避免和上下翻页抢。拖动时信息和操作列淡出，中间显示大号时间和预览帧，松手跳转。一屏宽对应全片，超过 3 分钟的视频一屏宽按 3 分钟算。

关注和主页分开

头像下的「+」关注；点头像或 @名字 进主页。第一次左滑时提示一次「UP 主页改为点头像」。

「⋯」打开菜单

替换原来的分享按钮，分享移进菜单。顶栏的「弹」一键开关弹幕，长按直接进弹幕设置。

评论不挡视频

面板 62% 高，视频缩到上方继续播放，点上方画面关闭。面板改成页面内的组件，不再是独立窗口，图片预览自然在最上层。

横屏视频

画面下方「全屏观看」，锁定方向也能进全屏（SENSOR_LANDSCAPE，退出时恢复）。转手机进全屏的老路径保留。

平板 · 折叠屏 · 双屏

画面顶天立地，空处放内容

大屏不再用固定的「视频框 + 两侧工具栏」，那样两边总会剩下大片空白。改成一条规则：先按折痕切区，再让画面贴满所在区域，剩下的空间按宽度放信息、评论或控制。下面每块屏都是同一个函数算出来的，切换视频方向和评论看它怎么变。

布局规则

  1. 先切区。折叠屏半开、双屏跨屏时，按折痕 / 铰链切成两片（沿用现有 WindowFold、FoldPanes）。画面只放第一片（左或上），不跨折痕；第二片放评论或控制。
  2. 画面贴边。竖屏视频高度顶满所在区域，贴左；横屏视频宽度顶满，贴顶。不居中，不加边距，不加圆角框。
  3. 能铺满就铺满。铺满所需的裁切，竖屏视频不超过 20%、横屏视频不超过 10% 时，直接放大铺满，信息叠在画面上。
  4. 剩下的空间放内容。右侧剩余宽度：小于 300 放竖排操作列；300 到 720 放信息栏（评论 / 相关 / 设置用标签切换）；720 以上拆成两栏。下方剩余高度：小于 360 放信息条，360 以上信息条下面接评论。
  5. 评论不盖画面。单区的横屏视频打开评论时，右侧让出 400 给评论，画面按第 2、3 条重新贴边。

落到代码

写成一个纯函数 resolveShortsLayout(window, fold, videoSize, commentsOpen)，输出每块区域的矩形和内容类型；手机、平板、电视都从它取布局。视频方向优先用播放器上报的宽高（电视端已经这样判断），元数据只做兜底。

这个函数放在 app:shared，下面这些机型的结果直接写成单元测试用例。

一个面板装下所有操作

右侧 360dp，外壳和主播放器的 TvMenuPanel 相同：左列分类「互动 / 评论 / 弹幕 / 画面 / 播放」，聚焦即切换；右列选项。每次打开都停在「互动 › 点赞」，长按 OK 再按 OK 就是点赞。

信息列只负责显示

竖屏时右侧常驻 UP 主、标题、点赞 / 投币 / 收藏状态和两条评论，焦点不需要挪过去。底部一行按键提示。

为什么不用 → 去按钮

谷歌系遥控器没有菜单键，长按 OK 是它们唯一的入口，所以这条路径必须稳；把操作收进面板后，←→ 才能完全交给快进退。

面板叠在画面上

电视沿用主播放器的做法：面板从右侧滑出叠在画面上，画面不缩。这是「评论不盖画面」规则在电视上的唯一例外，因为看电视时面板是短暂操作，关掉后画面完整。

弹幕

弹幕放在哪、怎么跟上

规则只有一条：弹幕不从按钮后面穿过，也不出视频框。斜线区域是默认显示区。

加载与同步

  • 整个刷刷只有一个弹幕引擎实例（DanmakuView），跟着当前条走，离开刷刷时释放。
  • 停稳 150ms 后拉当前 cid 的第一个分段（6 分钟一段，绝大多数刷刷视频一段就够）；当前条缓冲完成后预取下一条第一段；按 cid 缓存最近 3 条。
  • 进度来源是播放器池当前槽位的 positionMs；拖进度、快进退后调 notifySeek；长按 2× 时弹幕同步加速。
  • 拖动进度时弹幕淡出，松手后从新位置开始，不残留旧弹幕。

复用什么

  • 按 cid 拉分段的逻辑从 VideoPlayerV3ViewModel.loadDanmaku 抽成共用加载器，做法和 PlayUrlResolver 一样：播放器和刷刷共用一份。
  • 弹幕设置的界面复用 TvMenuPanel 的 danmakuOptions 和 TouchPanels 的 DanmakuPanel，参数从 PlayerMenuState 换成接口。
  • 防挡（蒙版）放到最后：竖屏视频是裁切显示的，蒙版坐标要按裁切换算。
实施

分四步做

顺序有依赖：先把手势和按键理顺（不加新能力），再做菜单（弹幕设置要放进去），然后弹幕，最后全屏和键盘。

  1. 交互修正

    只改手势、按键和布局，不加新能力。

    • ShortsCommon.kt：ShortsProgress 换成 ShortsScrubber（静止 2dp / 激活 6dp + 把手 + 时间，40dp 触摸区）；新增拖动时的大号时间和预览帧，预览帧复用主播放器的 VideoShot。
    • ShortsPhone.kt：去掉整页 detectHorizontalDragGestures；shortsGestures 加方向锁定的横向拖动，在 PointerEventPass.Initial 截获，横向锁定后翻页不动；暂停态播放键；头像「+」关注；标题展开。
    • 新文件 app:shared 的 ShortsLayout.kt：纯函数 resolveShortsLayout，输入窗口尺寸、WindowFold、视频宽高、评论是否打开，输出各区域矩形和内容类型；配单元测试，用例取「大屏与折叠」里的七种形态。
    • ShortsTablet.kt：去掉固定 9:16 视频框和两侧浮动工具栏，按 resolveShortsLayout 的结果摆放画面、信息栏、信息条和控制区；读 LocalWindowFold。
    • ShortsTv.kt：按键表改写；信息列改成只读状态加按键提示；快进时的时间与预览帧。

  2. 播放菜单

    一个模型，三种外壳。

    • 新文件 ShortsMenu.kt：ShortsMenuState 加 PhoneMenuSheet、TabletSettingsPage、TvShortsPanel。
    • ShortsPlayerPool.kt：setSpeed（跨条保持，boost 叠加在上面）；setAfterEnd（REPEAT_MODE_ONE / OFF 加播完回调翻页）；setQualityCap（重新解析当前条，新地址 prepare 好再换，回到原进度）。
    • ShortsViewModel.kt、Prefs.kt：shortsAfterEnd；把 toggleToView 接到界面。
    • 手机评论面板改成页面内组件，视频上移缩小。

  3. 弹幕

    • 新文件 ShortsDanmaku.kt：单实例 DanmakuView 加共用加载器；三端区域计算。
    • Prefs.kt：shortsDanmakuEnabled、shortsDanmakuArea。
    • ShortsPlayerPool.kt 的「不创建弹幕播放器」注释和逻辑一起去掉。

  4. 全屏与键盘

    • PhoneFullscreen 重做：控制层、切条、互动、「全屏观看」按钮。
    • 平板键盘、滚轮、右键、F 全屏。
    • 电视首次进入显示一次按键提示，复用 RemoteControlHintOverlay。

风险

风险处理
横滑拖进度和上下翻页抢手势方向锁定：过 10dp 且横向分量大于竖向 1.2 倍才算横滑；锁定后另一个方向不响应。
老用户习惯左滑进主页第一次左滑时提示一次「UP 主页改为点头像」。
谷歌系遥控器没有菜单键长按 OK 是唯一入口；沿用现有 CenterLong 对两种盒子的兼容。
切画质时黑屏新地址 prepare 好再换画面，保留当前帧。
低端电视盒子上弹幕卡顿引擎只有一个实例；面板打开时不暂停弹幕，但默认密度沿用主播放器设置。

不在这一轮：发弹幕（应用里还没有发送接口）、字幕、「不感兴趣」反馈（接口没确认）。

验收

怎么算做完

手机 / 平板

  • 暂停后拖到任意位置，松手后误差不超过 1 秒。
  • 斜着划（偏竖向）只翻页，不触发拖进度；横向 10dp 以内不触发。
  • 锁定方向时「全屏观看」能进全屏，返回键退出；全屏里上下滑能切条。
  • 评论面板里点图片，预览在面板之上；返回先关预览，再关面板。
  • 平板、折叠屏、双屏：画面在所在区域里上下或左右顶满，除视频本身的比例差外，屏幕上没有空白区。
  • 折叠屏半开、双屏跨屏：画面和任何按钮都不压在折痕 / 铰链上；展开、折叠、半开切换时不重新进入页面，当前条继续播放。

电视

  • 在 Television_1080p AVD 上把按键表逐条按一遍，用 uiautomator 读 content-desc 确认状态。
  • 无菜单键遥控器：长按 OK 能打开面板，再按 OK 完成点赞。
  • 「电视横屏」模式下的手机：单击、上下滑、横拖、长按都按触摸表生效。
  • 返回键顺序：面板 → 快进 → 导航轨，每次只退一层。
  • 切条后新弹幕在 300ms 内出现；拖进度后没有旧位置的弹幕残留。
