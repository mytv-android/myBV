01 · 形态规则

先看窗口，再看折叠

现有 DeviceProfile 继续决定宽度、输入方式与观看距离。折叠信息只增加分区约束，不把“折叠屏”变成第四种界面，也不按具体机型写分支。

窗口宽度：沿用当前四级

  • Compact < 600dp：底部六项导航，首页两列。
  • Medium 600–839dp：收起导航轨，Phone 内容，首页三列。
  • Expanded 840–1199dp：收起导航轨，Tablet 双栏详情。
  • Large ≥ 1200dp：220dp 展开导航轨，更多内容列。

物理形态：新增两条约束

  • 是否分区：isSeparating 决定能否把折叠边当成内容边界。
  • 边界在哪里：bounds 决定每块内容的真实宽高，比例不写死。
  • 是否遮挡：occlusionType = FULL 时，铰链区域完全留空。
  • 横还是竖：竖向分区左右排，横向分区上下排。
物理形态判定信号布局响应明确不做
外屏 / 普通手机无分区 Feature，Compact现有 Phone 单栏与底部导航不因为设备可折叠就改样式
完全展开FLAT，无分隔铰链按当前窗口宽度切换 Medium / Expanded / Large不把内屏简单拉成等比放大的手机
书本半开HALF_OPENED + 竖向折叠边左右逻辑页；首页主区＋推荐，视频画面＋评论文字、卡片和按钮不跨折叠边
桌面半开HALF_OPENED + 横向折叠边上半屏画面，下半屏进度、控制与评论不把播放控制留在弯折区域
双屏跨屏FULL + isSeparating；即使 FLAT按物理铰链分左右屏；动态列表＋详情不把 FLAT 当成可以跨铰链
横向展开 / 三折读当前窗口与实际 Feature完全展开时走 Expanded / Large；有多余 Feature 时逐区避让不假设支持半开，不锁定自然方向

优先级：真实分区边界优先于全局宽度级别。窗口即使是 Large，只要中间存在完全遮挡的物理铰链，也必须先分区，再在各自区域内选择现有组件。

02 · 首页

从底部导航，到双页浏览

外屏和平面展开完全沿用现有首页。只有真实分隔出现时，精选与继续观看留在主区，推荐流进入相邻区域；导航轨完整留在主区一侧。

04 · 动态

列表与详情，各守一块屏

动态天然适合列表—详情模式。选中项、左右滚动位置与评论状态彼此独立；从双屏收回单屏时，当前详情变成普通路由，返回后仍停在原列表项。

05 · 连续性与覆盖层

折叠只是重排，不是重新进入

沿用当前单 Activity 与稳定 NavHost 结构。姿态变化不创建新页面、不重置播放器，也不额外压入返回栈。

外屏记录内容身份

当前路由、bvid / cid、选中的动态与标签页。

展开保留浏览位置

首页与动态列表滚动位置、搜索文字、评论游标。

半开只移动布局边界

播放进度、画质、弹幕与播放器实例保持不动。

收回还原等价路径

双栏详情回到独立页面，焦点回到同一内容项。

弹窗与菜单

从哪块区域触发，就约束在哪块区域内。双屏上的评论抽屉、画质菜单和分享面板不跨物理铰链；紧凑单屏仍用现有底部抽屉。

触摸与方向键

焦点样式仍由输入方式决定。重排后把焦点映射到同一内容，不让焦点落入禁入区；每个逻辑区域记住自己的最后焦点。

滚动与手势

主区与辅助区独立滚动，不用一条长滚动容器跨两块屏。边缘返回手势跟随当前内容区，多窗口时只读取应用窗口。

内容间距：每个逻辑区域保留现有 16dp 页面边距。铰链宽度不是卡片间距，也不计入内容可用宽度；任何文本和可交互控件都不能落入 bounds。
不等宽分区：主区与辅助区跟随真实边界，可以是 60:40，也可以因多窗口而改变。不要为“书本”“双屏”写固定像素或固定 50:50 比例。
06 · 设计验收

不改变风格，只验证布局

下面每条都可以直接用窗口尺寸和模拟 FoldingFeature 验证，无需先按机型命名。

验收项通过标准重点回归
Compact / Medium 基线首页仍为 2 / 3 列；Medium 使用导航轨，现有样式不变外屏、普通手机、平面展开
竖向分区卡片、标题、按钮、弹幕设置均完全位于某一侧，没有内容穿过折叠边书本半开、双屏 FLAT
横向分区视频完整位于上半区，进度与控制完整位于下半区桌面半开、横向物理铰链
完全遮挡occlusionType = FULL 的范围内不绘制业务内容，不放点击目标双屏跨屏、弹出菜单
状态连续折叠、旋转、拖窗后视频从原位置继续；选中项与滚动位置不丢首页、动态、搜索、播放器
返回与焦点双栏切单栏不多一层返回；方向键焦点落在同一内容而非默认首项动态详情、外接键盘
三折与横折不依赖 HALF_OPENED，不锁定自然方向，密度变化后重新测量窗口完全展开、内外屏切换
